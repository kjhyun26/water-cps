1. 전체 구조

프로그램 여섯 개가 각자 돈다. 값이 오가는 길은 둘이다.

  • 물리 층: SQLite 파일 하나(water_cps.sqlite)의 표. 센서와 펌프·밸브가 장치에 전선으로 연결된 것을 흉내 낸다. 공정이 센서값을 쓰면 PLC가 읽고, PLC가 펌프 명령을 쓰면 공정이 읽는다.
  • 통신 층: EtherNet/IP(산업용 통신 규격). 장치마다 서버가 하나 있고 다른 장치가 거기서 읽거나 쓴다. Mininet 가상 네트워크 위에서 돈다.

예: 주입률 설정값이 17 mg/L이면 PLC2는 2,000 m³/h × 17 ÷ 1000 = 34 kg/h를 상태 표의 P201에 쓴다. 공정은 그 값을 읽어 pH 7.145를 AIT202에 쓰고, SIS가 그 pH를 읽는다.

Python을 둘로 나눈 이유: run.py는 시스템에 설치된 Mininet을 쓰고, 장치는 가상환경의 MiniCPS와 cpppo를 쓴다. 그래서 config.py와 init.py는 minicps를 import하지 않는다. 둘 다에서 불리기 때문이다.

3. 태그와 값이 오가는 길

태그는 (이름, 장치 번호) 짝이다. 번호는 그 센서·구동기가 연결된 장치다: 1=PLC1, 2=PLC2, 3=PLC3, 4=SIS, 0=공통. 이름 앞글자는 계장 기호 관례다(L 수위, F 유량, A 수질, P 펌프, XV 차단밸브).

물리 층 (상태 표)

태그뜻처음 값쓰는 쪽 → 읽는 쪽
SIM_TIME:0공정 시각 (초)0공정 → PLC1, PLC3
AIT101:1원수 탁도 (NTU)6.0바깥 → 공정, PLC1
LIT101:1착수정 수위 (m)3.5공정 → PLC1
FIT102:1생산 유량 (m³/h)2000.0공정 → PLC1
P101:1취수 펌프 (1 약, 2 강)2PLC1 → 공정
P201:2약품 펌프 명령 (kg/h)34.0PLC2 → 공정
AIT301:3침전수 탁도 (NTU)0.49공정 → PLC3
AIT202:4주입 후 pH7.145공정 → SIS
XV201:4약품 차단밸브 (1 열림, 0 닫힘)1SIS → 공정

처음 값은 config.py의 INITIAL_* 상수 하나씩에서 온다. 상태 표, 장치 서버, HMI가 모두 같은 상수로 시작한다. 공정만 아는 "필요 주입률"은 상태 표에 없고 공정 기록 파일에만 남는다. 센서로는 알 수 없는 값이기 때문이다.

통신 층 (장치 서버)

서버장치가 올리는 값밖에서 써 주는 값주기당 통신

통신 한 번은 cpppo 클라이언트 프로세스를 새로 띄우므로 약 0.08초 걸린다. 그래서 주기당 횟수를 이만큼으로 묶었다. 측정한 PLC2 주기는 평균 1.24초(쉬는 1초 포함)다.

4. 파일별 설명

공통config.py

상수, 태그, 주소, 상태 표 구조, 그리고 모든 장치가 쓰는 함수 셋.

  • to_number(text, previous): 읽은 글자를 실수로. 못 바꾸거나 nan·inf면 직전 값.
  • to_numbers(texts, previous_values): 여러 값 읽기 결과용. 길이가 물은 개수와 다르면 전부 직전 값.
  • write_initial_values(device, address, tags, values, check_tag): 자기 서버에 처음 값을 쓰고 확인 태그를 읽어 맞을 때까지 되풀이(최대 20번).

파일 끝의 assert 몇 줄이 import할 때마다 이 함수들과 처음 값을 점검한다. 예: to_number("b'", 2000.0) == 2000.0.

공통init.py

create_state(): 상태 표 파일, 지난 공정 기록(logs/process.csv), 지난 화면(logs/hmi_screen.txt)을 지우고 표를 처음 값으로 새로 만든다. run.py가 부르고, python3 init.py로 혼자 돌릴 수도 있다.

물리physical_process.py

WaterProcess(Tank). 수식 함수 셋(required_dose, dosed_ph, settled_turbidity)과 한 걸음 계산 step().

def step(self):
    # 0. 읽기: AIT101, P101, P201, XV201
    # 1. 수위: 취수 유량(2,400 또는 1,600) − 2,000 만큼 오르내림, 0~5 m로 자름
    # 2. 약품과 pH: 차단밸브가 닫히면 0, 아니면 P201 을 0~250 kg/h 로 자름
    # 3. 필요 주입률 = 9.8 + 3.0 × ln(원수 탁도)
    # 4. 침전수 탁도: (실제 − 필요) 를 600칸 줄 뒤에 넣고 맨 앞(5시간 전)을 꺼내 계산
    # 5. 공정 시각 += 30, 상태 표에 쓰고 기록 파일에 한 줄

pre_loop가 시작할 때 수식을 설계 문서 4-3절 표의 값으로 assert 점검한다. 줄은 처음에 기본값 기준 차이(+1.82)로 600칸을 채워 둔다. 안 채우면 처음 5시간 동안 나오는 물이 없어 잘못된 주입이 가려진다.

제어plc1.py 착수정 수위

if self.level <= LEVEL_LOW:      # 3.3 m
    self.intake_pump = 2          # 강
elif self.level >= LEVEL_HIGH:   # 3.7 m
    self.intake_pump = 1          # 약
self.set(P101, self.intake_pump)

그 사이 수위에서는 직전 상태를 유지한다(SWaT 예제와 같은 방식). 수위는 3.28~3.72 m 사이를 공정 약 24분 주기로 오르내린다. 물리 층의 SIM_TIME:0을 읽어 자기 서버의 SIM_TIME:1로 올린다. 이름은 같고 번호가 다르다.

제어plc2.py 약품 주입

self.dose_setpoint = to_number(self.receive(DOSE_SETPOINT, OWN_ADDRESS), self.dose_setpoint)
self.production_flow = to_number(self.receive(FIT102, PLC1_ADDRESS), self.production_flow)
chemical_pump_command = round(self.production_flow * self.dose_setpoint / 1000, 4)
self.set(P201, chemical_pump_command)

받은 설정값을 검사하지 않는다. 도메인 문서 2-1절의 "PLC는 값이 적절한지 따지지 않는다"를 그대로 옮긴 것이다. 5~50 mg/L 한계는 다음 단계에서 이 파일에 넣는다(8절).

제어plc3.py 침전수 탁도 경보

한 주기 판정은 cycle()에 있다. 시간은 주기 횟수가 아니라 SIM_TIME의 차이로 센다.

if self.settled_turbidity > TURBIDITY_LIMIT:      # 1.0 NTU
    self.over_minutes += elapsed_minutes
else:
    self.over_minutes = 0.0
alarm = 1 if self.over_minutes >= TURBIDITY_ALARM_MINUTES else 0   # 30분

예: 공정 30초마다 2.0 NTU를 읽으면 59번째에 29.5분(경보 없음), 60번째에 30분(경보). 정확히 1.0이 오면 0으로 돌아간다.

제어sis.py pH 차단

한 주기 판정은 cycle()에 있다. 다른 PLC의 서버는 읽지 않는다.

in_range = PH_LOW <= self.ph <= PH_HIGH                 # 5.8~8.5 (경계 포함)
self.out_of_range_count = 0 if in_range else self.out_of_range_count + 1
if self.out_of_range_count >= SIS_TRIP_COUNT and self.valve == 1:   # 2번 연속
    self.valve = 0
...
if request == 1 and self.valve == 0 and in_range:      # 복귀는 pH 가 범위 안일 때만
    self.valve = 1
self.set(XV201, self.valve)                             # 매 주기 쓴다
  • pH가 [5.75, 7.0, 5.75]로 오면 닫히지 않는다(중간에 횟수가 0이 됨). [5.75, 5.75]면 두 번째에 닫힌다.
  • 복귀 요청은 받아들였든 아니든 서버에서 0으로 지운다. 범위 밖일 때 넣은 요청이 남아 있다가 pH가 돌아오는 순간 저절로 열리는 일을 막는다.
  • 밸브를 바뀔 때만이 아니라 매 주기 쓰는 이유: 쓰기 한 번이 실패하면 SIS는 "닫힘"인데 상태 표는 "열림"인 채로 남기 때문이다.

5. 공정 수식

수식예시
필요 주입률 = 9.8 + 3.0 × ln(원수 탁도)6 NTU → 15.18, 300 NTU → 26.91 mg/L
실제 주입률 = 약품 유량 × 1000 ÷ 2,00034 kg/h → 17 mg/L
주입 후 pH = 7.4 − 0.015 × 실제 주입률17 → 7.145, 110 → 5.75 (SIS 작동)
침전수 탁도 = 0.4 + 0.15 × 모자란 양² 또는 0.4 + 0.05 × 넘친 양 (5시간 전 값)2 모자람 → 1.0, 2 넘침 → 0.5, 9.9 모자람 → 15.1 NTU

도메인 문서의 수치(평상시 필요량 15.38 mg/L, 침전 지연 4~7시간)에 가깝게 잡은 합성 모델이다. 실제 정수장 자료로 맞춘 것이 아니다.

6. 실패를 다루는 규칙

MiniCPS와 cpppo는 실패해도 예외를 내지 않고 엉뚱한 값을 돌려준다. 2026-11-18에 직접 확인한 모습과 코드의 처리:

상황돌아오는 값처리
상대 서버가 꺼진 채 receive"b'" (0.06초)to_number → 직전 값
상대 서버가 꺼진 채 receive_multiple[]to_numbers → 전부 직전 값
없는 태그가 섞인 receive_multiple앞의 것만 (3개를 물었는데 1개)to_numbers → 전부 직전 값 (칸이 어긋나지 않게)
SQLite 오류 중 getNoneto_number → 직전 값
서버가 뜨기 전에 send값이 사라짐 (오류 없음)write_initial_values가 다시 읽어 확인하고 되풀이
1e-05처럼 소수점 없이 찍히는 실수 보내기클라이언트가 정수로 읽다 실패, 값이 안 바뀜보내기 전 round(값, 4), HMI는 nan·inf 거절

기록에 남는 오류 한 줄은 정상이다. 장치마다 첫 쓰기 때 서버가 아직 안 떠서 ConnectionRefusedError가 한 번 찍히고, 바로 뒤에 initial values written to ...가 찍힌다.

9. 모델 학습 데이터 만드는 법

설계안이다. 지금 코드 위에 어떻게 붙이면 되는지 적은 계획이고, 아직 구현하거나 시험하지 않았다. 함수 이름과 파일 이름은 제안이다.

9-1. 무엇을 만드나

9-3. 붙일 것 세 가지

새 파일water_cps/scenarios.py: 원수 시나리오

공정 시각을 받아 원수 탁도를 돌려주는 함수. 이 계층은 원수를 정하지 않으므로(1-3절) 바깥에 둔다.

def raw_turbidity(sim_time_seconds, storms):
    """평상시 6 NTU ± 1 에, storms 목록의 호우를 얹는다. 호우 하나는 (시작 초, 정점 NTU)."""
    hours = sim_time_seconds / 3600
    value = 6.0 + math.sin(hours / 24 * 2 * math.pi)          # 하루 주기로 천천히 흔들림
    for start, peak in storms:
        since = (sim_time_seconds - start) / 3600
        if 0 <= since < 3:                                      # 3시간에 걸쳐 오름 (로그 눈금 직선)
            value = max(value, 6.0 * (peak / 6.0) ** (since / 3))
        elif 3 <= since < 15:                                   # 12시간에 걸쳐 내림
            value = max(value, peak * (6.0 / peak) ** ((since - 3) / 12))
    return value

도메인 문서 4-6절처럼 "30일 동안 호우 3번"을 만들려면 storms=[(5*86400, 300), (14*86400, 150), (23*86400, 400)]처럼 준다. 조류(탁도는 그대로인데 필요 주입률만 오르는 경우)를 넣으려면 공정의 required_dose()에 "숨은 조류 영향" 값을 더하는 입력이 하나 더 필요하다(공정 쪽 변경).

새 파일water_cps/operator_policy.py: 운영자 흉내

학습 기록의 주입률은 운영자가 넣은 값이다(도메인 문서 2-5절). 운영자처럼 정하는 규칙이 있어야 "운영자를 따라 배운 값"이 생긴다.

class OperatorPolicy:
    """하루 한 번 자-테스트로 필요량을 재고, 2 mg/L 넉넉히 넣는다. 그 사이에는 값을 그대로 둔다."""
    def __init__(self, overdose=2.0, jar_test_hours=(9,)):
        self.overdose, self.jar_test_hours, self.setpoint = overdose, jar_test_hours, 17.0
    def setpoint_at(self, sim_time_seconds, true_required_dose):
        hour = int(sim_time_seconds // 3600) % 24
        if hour in self.jar_test_hours and sim_time_seconds % 3600 == 0:
            self.setpoint = true_required_dose + self.overdose   # 자-테스트 = 실제 필요량을 재는 실험
        return self.setpoint

자-테스트를 흉내 낼 때만 공정의 required_dose()(정답)를 쓴다. 실제로도 자-테스트는 물을 직접 실험해 필요량을 알아내는 일이기 때문이다. 호우가 오면 다음 자-테스트까지 운영자 값이 모자라므로, 도메인 문서 2-4절의 "한두 시간 비는" 상황이 그대로 나온다.

새 파일water_cps/dataset/build_dataset.py: 돌리고 묶기

for step_number in range(30 * 86400 // 30):                  # 30일
    now = step_number * 30
    raw = raw_turbidity(now, storms)
    put('AIT101', 1, raw)                                    # 바깥 값: 원수
    dose = operator.setpoint_at(now, required_dose(raw))      # 운영자가 정한 주입률
    put('P201', 2, 2000.0 * dose / 1000)                     # PLC2 가 할 계산

  • 나누기: 시간순으로 나눈다(예: 앞 21일 학습, 뒤 9일 시험). 무작위로 섞으면 5시간짜리 줄들이 겹쳐 학습과 시험에 같은 물이 들어간다.
